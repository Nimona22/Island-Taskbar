# BRAND.md

> **Status:** Draft v0.1  
> **Product:** IslandTaskbar (working name)  
> **Purpose:** Record the product's identity decisions without inventing brand choices that have not yet been approved.

## 1. Brand Overview

IslandTaskbar is a Windows desktop application that replaces the visible Windows taskbar with one unified, custom interface.

The experience combines:
- The compact, top-attached presence of a laptop notch.
- The expandable, contextual interaction of a Dynamic Island.
- The everyday utility expected from a Windows taskbar.
- Additional system and productivity features that belong naturally in the same interface.

The brand should communicate that this is a capable Windows utility with a polished, modern interface—not merely a cosmetic theme.

## 2. Product Name

- **Current working name:** IslandTaskbar
- **Short name used in conversation:** Island
- **Public product name:** Not yet finalized.
- **Naming rule:** Use `IslandTaskbar` in project files and technical documentation until the public name is approved. Do not rename namespaces, solution files, package identifiers, or assets based on an unapproved naming idea.

## 3. Brand Purpose

Make the Windows desktop experience feel more unified, personal, and fluid by bringing taskbar functionality and contextual interactions into one thoughtfully designed interface.

## 4. Brand Promise

One visible taskbar that feels cohesive, remains useful throughout the day, and adds capability without getting in the user's way.

This is a product direction, not a claim that every Windows taskbar feature has already been implemented.

## 5. Brand Personality

The intended personality is:

- **Polished:** Careful visual details and consistent behavior.
- **Calm:** Avoid unnecessary motion, noise, and interruption.
- **Capable:** Prioritize useful, dependable functionality over decoration.
- **Modern:** Use contemporary desktop interaction patterns without copying another product wholesale.
- **User-respecting:** Preserve user control, provide clear settings, and avoid surprising behavior.

## 6. Voice and Product Language

Use language that is:
- Clear and direct.
- Friendly without being overly casual.
- Short enough to work in compact UI surfaces.
- Honest about status, permissions, limitations, and errors.

Avoid:
- Exaggerated marketing claims.
- Technical jargon in user-facing labels.
- Unclear labels such as “Magic” or “Boost” when a precise action name is possible.
- Copy that implies a feature works when it is still a placeholder.

## 7. Visual Identity

The visual system is defined in [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md).

Current direction:
- A compact, top-centered notch in its idle state.
- A horizontally oriented expanded island.
- Translucent, glass-inspired surfaces used with restraint.
- Smooth, purposeful transitions.
- Clear hierarchy and legible controls.

The final logo, icon, brand colors, typography choices, and detailed visual assets are **not yet approved**. Do not treat placeholder colors or geometric symbols in prototypes as final brand assets.

## 8. Product and Brand Boundaries

IslandTaskbar should:
- Feel like a native part of the Windows desktop.
- Remain recognizably its own product.
- Complement Windows behavior rather than misrepresenting itself as an official Microsoft product.
- Use familiar interaction patterns where they improve usability.
- Avoid copying another product's exact logo, assets, or distinctive visual identity.

## 9. Naming and Asset Rules

Until the identity is finalized:
- Use the working name `IslandTaskbar`.
- Use neutral, clearly identified placeholder icons and assets.
- Keep brand assets replaceable; do not hard-code a temporary logo into unrelated components.
- Store approved brand assets in a dedicated assets location once the project structure is defined.
- Record final naming and identity decisions in `DECISIONS.md` when that document is created.

## 11. Change Control

Brand decisions should be changed deliberately:
1. Propose the change and explain why it improves the product.
2. Check consistency with `DESIGN_SYSTEM.md` and existing UI.
3. Get product-owner approval for identity decisions.
4. Record approved decisions in `DECISIONS.md` once it exists.
5. Update this document and affected assets together.
